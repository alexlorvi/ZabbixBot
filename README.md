# ZabbixBot — інтеграція Telegram ⇄ Zabbix

Telegram-бот для моніторингу Zabbix: авторизовані користувачі (ті, кого знайдено в Zabbix за медіа Telegram, `sendto` = chat id) можуть переглядати свої відкриті проблеми, шукати хости, запускати базову мережеву діагностику й керувати особистими налаштуваннями сповіщень прямо з чату.

## Можливості

### Команди Telegram

**Доступні всім** (`telegram.commands`):
- `/start` — привітання, показує ваш chat id.
- `/help` — список доступних команд (адміністраторам додатково показується статус і адмінські команди, напр. `/reset`).

**Доступні лише авторизованим Zabbix-користувачам** (`telegram.user_commands`):
- `/ping <host> [count]` — пінг хоста (IP або ім'я, за замовчуванням 4 пакети, максимум `net.ping_max_count`, 10000). **До 100 пакетів** результат оновлюється в реальному часі в одному повідомленні. **Понад 100** — бот відповідає «взято в роботу», пінг іде у фоні (`app:ping-job`), а по завершенні відповіддю на команду приходить **лише підсумок** (передано/отримано/втрати/rtt). Один фоновий пінг на чат одночасно. Якщо фоновий процес не стартував (немає PHP CLI, `exec` заборонений, миттєва помилка), бот відповідає «Не вдалося запустити пінг у фоні», а причина — в `logs/main-*.log`; вивід самих завдань — у `logs/ping-job.log`. Ручна перевірка на сервері (від користувача веб-сервера): `sudo -u www-data php console.php app:ping-job <chat_id> 127.0.0.1 3 --lang=ua` — підсумок має прийти в чат.
- `/events` (або аліаси групи з `config.zabbix.groups`, напр. `/zabbix`, `/zabbixList`, `/zabbixFull`) — відкриті проблеми по групі; аліас зі словом `Full` у назві дає докладний звіт, інші — короткий список.
- `/menu` — панель швидкого доступу (повний/короткий звіт, довідка, налаштування); вигляд залежить від персонального налаштування "стиль меню" — inline-кнопки (за замовчуванням) або звичайна клавіатура.
- `/host <IP або частина імені>` — пошук хоста: якщо збіг один — картка хоста (стан, інтерфейси, активні проблеми, кнопки Ping/Cisco/APC і «🔄 Оновити»); якщо кілька — список inline-кнопок для вибору.
- `/reset` — **лише для адмінів** (інші його не бачать у `/help` і `/menu`; в `/menu` для адміна є кнопка «Скинути кеш»): скидає кеш списку Zabbix-користувачів і груп. Адмінство визначається членством у Zabbix-групі (`config.zabbix.admin_group`), а не окремим списком chat id.
- `/cisco <IP>` — стан портів Cisco-свіча через SNMP (`commands/get_Int_status_cisco2.sh`).
- `/apc <IP>` — діагностика карти керування APC (ping + SNMP + перевірка портів).
- Під результатом `/ping`, `/cisco`, `/apc` — кнопка **«🔄 Повторити»** (та сама команда з тими ж параметрами).
- `/settings` — особиста панель налаштувань (див. нижче), керується виключно inline-кнопками з редагуванням одного повідомлення.

**Виправлення порожньої команди.** Якщо надіслати `/ping`, `/cisco`, `/apc`, `/host` чи `/events` без аргументів, бот відповідає довідкою. Якщо потім **відредагувати** своє повідомлення (напр. дописати `/ping 8.8.8.8`), довідка зникає, а команда виконується. Працює протягом 48 год (обмеження Telegram на видалення повідомлень) і лише для повідомлень, на які бот відповів довідкою — редагування інших повідомлень команди не перезапускають.

**Додаткові текстові формати** (розпізнаються без реєстрації як окрема команда):
- `/ev<id>` — деталі конкретної Zabbix-події за eventid.

Детальний звіт про проблему містить: критичність (кольоровий маркер), час появи і скільки вона відкрита, хост, eventid (`/ev<id>`), назву, теги, позначку про квитування та коментарі. Показуються лише проблеми з увімкнених тригерів на ввімкнених (моніторених) хостах.
- `/hostid<id>` — відкриває картку хоста (використовується inline-кнопками з `/host`, вручну викликати не потрібно).
- `/<N>sec` — переводить N секунд у людський формат (днів/годин/хвилин).
- `/<N>h`, пресети `/24h`, `/72h` — проблеми, відкриті довше вказаної кількості годин.

### Особисті налаштування (`/settings`)

Панель редагує **одне й те саме повідомлення** (через `editMessageText`), нічого не спамить новими:
- **Мова** — перемикає інтерфейс бота (`en`/`ua`).
- **Стиль `/menu`** — inline-кнопки або звичайна Telegram-клавіатура.
- **Способи сповіщення** — усі media вашого Zabbix-користувача **з сервера**: назва медіатипу (як у Zabbix; якщо кілька одного типу — з адресою), поточні рівні критичності, позначка «вимкнено в Zabbix». Кнопка кожного відкриває підменю: мультиселект з 6 рівнів (Not classified…Disaster) і «Назад». Зміна одразу пишеться в Zabbix у цей media через `user.update` (сервісний `zabbix.apikey` повинен мати права редагувати чужі `user`-об'єкти). Media з каталогу користувачів (LDAP, provisioned) показуються лише для перегляду. Назви медіатипів кешуються (`zabbix.mediatype_cache_ttl`, 1 год; `/reset` скидає).

Головне меню має кнопку «Закрити» (видаляє повідомлення панелі).

### Сповіщення з Zabbix (`alert.php`)

Бот приймає сповіщення з Zabbix (webhook-медіатип) і шле їх у Telegram. Повідомлення про відновлення (та оновлення) приходить **відповіддю** на повідомлення про проблему: `message_id` проблеми зберігається у файлі `alerts/<eventId>_<chatId>.json` і видаляється після відновлення. Якщо проблему бот не бачив — просто звичайне повідомлення. Медіатип Zabbix створюється командою `php console.php app:mediatype install --lang=ua|en` (мова шаблонів і кнопок; друкує новий mediatype-id; з `--mediatype-id=N` замінює наявний N) або імпортом [docs/zbx_export_mediatypes.yaml](docs/zbx_export_mediatypes.yaml) — деталі в [docs/zabbix-alerts.md](docs/zabbix-alerts.md).

### Квитування і коментарі з Telegram

- Під сповіщенням про проблему і під `/ev<id>` є кнопки **✅ Квитувати** і **💬 Коментар**.
- «Квитувати» підтверджує проблему в Zabbix; після цього кнопка зникає (лишається «Коментар»).
- «Коментар» — бот просить надіслати текст відповіддю на його повідомлення.
- Також можна просто **відповісти (reply) текстом** на будь-яке повідомлення бота про одну подію: сповіщення про проблему, оновлення чи відновлення, картку `/ev<id>`. Текст стає коментарем до проблеми в Zabbix. Відповіді на списки з кількох подій ігноруються — там незрозуміло, до якої події коментар.
- Дії виконуються **вашим особистим токеном** Zabbix: у історії проблеми видно саме вас, і діють ваші права. Ваша роль у Zabbix має дозволяти «Acknowledge problems» / «Add problem comments», а група — мати доступ до хоста. Якщо Zabbix відмовить, бот покаже текст помилки.
- Кнопки під сповіщеннями вимикаються `alerts.ack_buttons = false`.

### CLI (`console.php`)

```
php console.php app:retry-messages --limit=5     # повторно відправити повідомлення з черги (якщо був збій проксі/мережі)
php console.php app:send-message <chatId> "text" # разова відправка довільного повідомлення
php console.php app:top200-sync                  # синхронізувати групу TOP200 з WogRouters (для cron)
php console.php app:webhook set|info|del         # керування Telegram-вебхуком, див. розділ нижче
php console.php app:mediatype install|export --lang=ua|en  # медіатип Zabbix для alert.php: створити/замінити (--mediatype-id) або лише YAML
```

## Вимоги

- PHP ≥ 8.1, розширення `curl`, `json`, `mbstring`.
- Опційно `ext-sodium` — для шифрування персональних Zabbix API-токенів (`zabbix.token_key`); без нього токени зберігаються нешифрованими (права файлу `0600`).
- Zabbix API-ключ (сервісний) із правами на `user.get`/`user.update` — друге потрібне саме для роботи `/settings` (зміна severity в чужих `media`).
- Користувачі повинні мати в Zabbix медіа типу Telegram, де `sendto` = їхній Telegram chat id.

## Встановлення

```bash
composer install
cp config/config.php.sample config/config.php
```

Далі відкрийте `config/config.php` і заповніть реальні значення (бот-токен, Zabbix host/apikey тощо) — див. розділ нижче.

## Перед запуском

- [ ] `net.snmp_community_cisco` — якщо порожньо, `/cisco` завжди повертатиме помилку.
- [ ] `net.snmp_community_apc` — стоїть дефолт `'public'`, перевірте, чи це дійсно community вашої інфраструктури.
- `zabbix.admin_group` — назва групи Zabbix, членство в якій дає адмінські права в боті.

## Куди вносити налаштування

**Усі налаштування — у `config/config.php`** (реальний, гітігнорений файл; `config/config.php.sample` — шаблон з коментарями, завжди синхронізуйте структуру, коли додаєте нові ключі). Файл повертає один масив з секціями:

| Секція | Що там |
|---|---|
| `telegram` | `bot_token`, `webhook_url`, опційно `webhook_secret` і `rate_limit`, `lang` (мова за замовчуванням для нових користувачів), опційно `proxy`, списки команд `commands`/`user_commands` |
| `zabbix` | `host`, `apikey` (сервісний ключ — потребує й прав на `user.update`, див. вище), `admin_group` (назва групи Zabbix, чиї учасники — адміни бота для `/reset`), `user_token_ttl_days`, опційно `token_key` (base64 32 байти для шифрування токенів), `groups` (аліаси для `/events`) |
| `net` | `snmp_community_cisco`, `snmp_community_apc` — для `/cisco` і `/apc` |
| `logger` | шлях, рівні логування, `keep_days` (ротація) |
| `emoji` | емодзі, що використовуються в текстах повідомлень |

Тексти, які бачить користувач (описи команд, повідомлення), — у `config/messages.php` (англійська, також дефолт-фолбек) і `config/messages.ua.php` (українська). При додаванні нової команди текст додається в обидва файли під ключем `command.<name>.*`.

## Робота з вебхуком

Бот — вебхук-бот: Telegram сам стукає на `index.php` при кожному вхідному update. Потрібен публічний HTTPS-URL, що веде на `index.php` (`telegram.webhook_url` у конфізі має збігатися з реальним URL). Усе керування вебхуком — через CLI-команду `app:webhook` (`console.php`), `index.php` сам по собі нічого не реєструє й не видаляє.

```
php console.php app:webhook set    # зареєструвати/перереєструвати вебхук на telegram.webhook_url
php console.php app:webhook info   # поточний стан: url, pending_update_count, остання помилка доставки тощо
php console.php app:webhook del    # видалити вебхук (бот перестає отримувати update)
```

**Реєстрація/перереєстрація:**
1. Заповніть `telegram.bot_token` і `telegram.webhook_url` у `config/config.php`.
2. (Опційно, рекомендовано) Задайте `telegram.webhook_secret` — випадковий рядок; Telegram повертатиме його в заголовку `X-Telegram-Bot-Api-Secret-Token`, і бот перевірятиме це при кожному update (403 при невідповідності) — захист від підробних запитів на ваш URL.
3. `php console.php app:webhook set` — виведе `SUCCESS: WebHook -> <url>` або `ERROR`. Те саме — після оновлення бота, якщо змінився список типів update (зараз `message`, `edited_message`, `callback_query`): без перереєстрації Telegram не надсилатиме нові типи.

⚠️ **Порядок важливий**: якщо вмикаєте `webhook_secret` на вже зареєстрованому вебхуку — спершу додайте ключ у конфіг, потім виконайте `app:webhook set` знову. Інакше бот почне відповідати 403 на всі запити, бо Telegram ще не знає про секрет.

**Локальна розробка:** без публічного HTTPS Telegram не достукається до `index.php` — для локального тестування потрібен тунель (ngrok тощо) з HTTPS-URL, прописаним у `webhook_url` перед `app:webhook set`.
